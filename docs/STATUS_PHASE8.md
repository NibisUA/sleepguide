# SleepGuide — що зроблено і що залишилось

> Стан на кінець **Phase 8 із 11**. Документ написаний для власника проєкту. Архів із кодом на цей момент:

## 1. Коротко

**SleepGuide** — Telegram Mini App для обліку сну, тренувань, стресу й екранного часу, яка з часом
показує особисті закономірності («що впливає на мій сон?»).

| Що | Як |
| --- | --- |
| Інтерфейс | React 19 + TypeScript + Vite + Tailwind 4 + TanStack Query + react-i18next (uk/en), графіки власним SVG |
| Бекенд | FastAPI + async SQLAlchemy 2 + Alembic + PostgreSQL 16, бот aiogram 3 (webhook) у тому ж процесі |
| Де працює | Oracle Cloud Always Free VM (Ubuntu, ARM), Docker Compose: `db`, `backend`, `web` (Caddy з HTTPS) |
| Адреса | `https://sleepmaxxing.pp.ua` (один домен: фронтенд + `/api`) |
| Репозиторій | приватний `NibisUA/sleepguide` на GitHub |
| Розмір коду | ≈ 3 300 рядків Python, ≈ 4 300 рядків TypeScript, 129 тестів |

**Загальний прогрес:** фази 1–8 із 11 написані. **Фази 1–4 перевірені в бойових умовах** (ти запускав
тести, збирав фронтенд, перевіряв бота й нагадування). **Фази 5–8 написані без можливості запустити
фронтенд і API-тести** (середовище без інтернету), тому їх треба перевірити першими, див. розділ 4.

## 2. Що вже зроблено

### Phase 1–2: основа
- Репозиторій, Docker Compose, міграції, авторизація через Telegram `initData` (перевірка HMAC і свіжості),
  короткоживучий JWT, dev-вхід без Telegram (лише `ENV=dev`).
- Продакшен: Oracle VM, Caddy із автоматичним HTTPS, бот у режимі webhook, нічний дамп бази (`deploy/backup.sh`).

### Phase 3: сон і Sleep Score (твоя версія + мої виправлення)
- Кнопки **Start / Stop**, ретроспективний запис «забув натиснути», редагування й видалення сесій.
- Правила: день сесії = дата пробудження в часовому поясі користувача; сон < 3 год вважається денним
  (не входить у Score); одна відкрита сесія на користувача; не довше 20 год; перетини заборонені;
  якщо сесія відкрита понад 14 год, потрібно вказати час пробудження.
- **Sleep Score** (єдина складена оцінка продукту): тривалість 40 + регулярність 30 + борг сну 20 +
  час відходу 10; перші дні без історії працює спрощена версія з позначкою «мало даних». Розбивка за
  компонентами завжди видна, оцінка рахується «на льоту».
- Історія: графіки Score й тривалості (7/30 днів), heatmap за роками, вибраний день зі списком сесій.
- Налаштування: ціль сну, бажаний час відходу, мова (uk/en), часовий пояс (береться з пристрою).

### Phase 4: нагадування в боті
- Вечірнє нагадування з кнопкою «🌙 Почати сон» (раз на день, не пізніше ніж за 90 хв після призначеного часу,
  пропускається, якщо сон уже триває).
- Тихе ранкове нагадування «☀️ Я прокинувся» (лише для відкритої сесії віком 5–14 год, 07:00–12:00 за
  місцевим часом, раз на сесію).
- Команди `/sleep` і `/wake`; після зупинки бот показує тривалість і Sleep Score.
- Планувальник — цикл усередині бекенду (щохвилини), відправки захищені від дублів атомарним UPDATE,
  заблокований бот автоматично вимикає нагадування.

### Phase 5: тренування
- Таймер: тип (зал, вдома, біг, футбол, ходьба, інше) і інтенсивність (легко … дуже важко), коригування при завершенні.
- Забутий Stop: тренування понад 6 год вимагає вказати реальний кінець. Скасування помилкового старту.
- Історія: кількість, загальний час, графік «хвилини за день», список із редагуванням, ретро-запис.
- Правила: без перетинів, не довше 6 год, день = місцева дата початку, оцінки немає.

### Phase 6: стрес
- Один тап по 1–5 зберігає оцінку; потім необов'язково причина (навчання, робота, стосунки, гроші,
  сон, тренування, особисте, інше) і «Скасувати».
- Кілька записів на день; значення дня = середнє (1 знак), також зберігається максимум.
- Історія: середнє, максимум, кількість, графік за днями (колір за рівнем), список, ретро-запис.

### Phase 7: екранний час і токени для Shortcuts
- Ручна форма: загальний час і час за 2 години перед сном (години + хвилини), будь-який день за останній рік,
  повторний запис дня замінює попередній.
- Історія: середні, діаграма (жовтий відсік — перед сном), список; записи від Shortcuts позначені.
- **Персональні API-токени** (Налаштування → Інтеграції): до 10 активних, показуються один раз, у базі лише
  SHA-256-хеш, відкликання. Токен приймають лише три запити (початок сну, кінець сну, запис екранного часу);
  читати дані чи керувати токенами з ним не можна.
- Ліміти: 10 невдалих спроб з однієї адреси за 5 хв, 120 запитів на токен за хвилину.
- Покрокова інструкція iOS Shortcuts: `shortcuts/README.md`.

### Phase 8: підсумок дня й швидкий запис
- `GET /api/v1/days/{дата}`: сон (Score + сесії), тренування, стрес, екранний час для одного дня.
- Home: три плитки за сьогодні; тап відкриває підсумок дня (з перемиканням на попередній/наступний день).
- Кнопка **«+»** у нижньому меню: вибір «сон / тренування / стрес / екранний час» → прокрутка до картки.
- Історія: кнопка «Підсумок дня» у блоці вибраного дня.
- Вкладка **«Інсайти»**: заглушка з прогресом (ночей даних із 14).

### Принципи, які вже закладено
- Часи зберігаються в UTC, «день» рахується в часовому поясі користувача.
- Бізнес-правила — чисті функції в `backend/app/analytics/` (легко тестувати).
- Помилки мають єдиний формат `{"detail": {"code": ..., "message": ...}}`, фронтенд показує текст за кодом.
- Усі тексти в `uk.json` і `en.json`, без жорстко вшитих рядків.
- Без важких залежностей: графіки й heatmap — власний SVG.
- Секрети лише в `.env.prod` на сервері, у репозиторій не потрапляють.

## 4. Що робити далі (по порядку)

### Крок 0. Стабілізація (зробити першим, ~1 вечір)
1. На комп'ютері: `cd backend; python -m pytest`, `cd ../frontend; npm run typecheck; npm run build`.
   Надіслати мені вивід, якщо є помилки, виправимо.
2. Задеплоїти: `git push`, на сервері `cd ~/sleepguide && git pull && dc up -d --build`,
   `dc logs --tail 40 backend` (мають застосуватися міграції `0003`–`0005`).
3. Пройти ручну перевірку (розділ 6) у Telegram на iPhone.
4. Налаштувати Shortcuts за `shortcuts/README.md` і повідомити, де інтерфейс відрізняється.

### Phase 9: двигун інсайтів (головна цінність продукту)
Детермінований аналіз без AI.
- Чотири правила: (1) багато екранного часу перед сном і коротший сон; (2) ночі після днів із
  тренуванням і сон; (3) дні з високим стресом (≥ 4) і Sleep Score тієї ночі; (4) вікно відходу до сну
  з найкращими оцінками.
- **Пороги:** ≥ 14 днів даних, ≥ 5 днів у кожній порівнюваній групі, помітна різниця (≥ 20 хв сну або
  ≥ 8 пунктів Score). Формулювання лише як закономірність («у тебе сон зазвичай коротший…»), без причинності,
  із підписом «на основі N днів».
- Збереження в таблиці `insights` (тип, параметри JSON, дата), тексти з i18n-ключів; ендпоінти
  `GET /insights`, `GET /insights/progress`; картки на вкладці «Інсайти» і «останній інсайт» на Home.
- Dev-генератор демо-даних (~60 днів із закладеними залежностями), який відмовляється працювати поза `ENV=dev`.
- Тести кожного правила, включно зі сценаріями «мало даних» і «різниці немає».

### Phase 10: шліфування
- Порожні, завантажувальні й помилкові стани на кожному екрані, скелетони; без «сирих» кодів помилок.
- Heatmap на телефоні відкривається на поточному місяці (зараз гортається від січня).
- Типи API генеруються з OpenAPI (`npm run gen:api`) замість рукописних.
- CI у GitHub Actions: `ruff`, `pytest`, `typecheck`, `build`.
- Вимірювання розміру бандла (було 108 КБ gzip на Phase 4), `staleTime` для запитів, `EXPLAIN` повільних запитів.
- Telegram-тема, safe-area, доступність (aria-мітки), перевірка на малому екрані й на Android.

### Phase 11: реліз і експлуатація
- **Приватність:** `GET /me/export` (усі дані користувача JSON), `DELETE /me` (каскадне видалення, відкликання
  токенів) з підтвердженням у Налаштуваннях; політика приватності (uk/en) із посиланням у боті й застосунку.
  Текст політики — чернетка, її має переглянути людина.
- Бот: опис, команди `/help`, `/privacy`.
- Експлуатація: ротація логів Docker, моніторинг `/health` (наприклад, UptimeRobot), **перевірене відновлення
  з бекапу** і копія дампів поза сервером, `unattended-upgrades`, вхід по SSH лише за ключем, обмеження
  швидкості для входу, нотатки про ротацію секретів, чек-ліст релізу, бета-тест.

### Після MVP (свідомо не робимо зараз)
Рекорди/PR (потрібна таблиця `exercises`), імпорт сну з Apple Health через Shortcuts, розпізнавання скриншота
екранного часу, діапазони 90 днів/усе, персональні базові лінії, нагадування за патерном, серії й досягнення,
картка для шерингу, стадії сну (потрібен годинник).

| № | Що | Чому важливо | Що робити |

| 12 | Рядки в Git показують попередження про CRLF | шум у виводі | один раз: `Set-Content -Encoding ascii .gitattributes "* text=auto eol=lf"` |

## 6. Ручна перевірка (чек-ліст для Telegram)

1. **Сон:** `/sleep` і `/wake` у боті; кнопки «Почати сон»/«Я прокинувся» в застосунку; ретро-запис; редагування;
   карточка Sleep Score з розбивкою.
2. **Нагадування:** увімкни вечірнє на 2–3 хв уперед → повідомлення з кнопкою → кнопка стартує сон.
3. **Тренування:** старт → зміна типу й інтенсивності → «Завершити» (після хвилини); ретро-запис; спроба перетину
   (має відмовити); «Скасувати тренування».
4. **Стрес:** тап «4» → «Збережено»; вибір і зняття причини; «Скасувати»; ретро-запис; графік.
5. **Екранний час:** форма за вчора (5 год 18 хв, перед сном 34 хв); повторний запис замінює; графік і список.
6. **Токени:** створити, скопіювати; з комп'ютера
   `curl.exe -X POST https://sleepmaxxing.pp.ua/api/v1/sleep/start -H "Authorization: Bearer sg_..."` → JSON;
   `curl.exe https://sleepmaxxing.pp.ua/api/v1/me -H "Authorization: Bearer sg_..."` → `401`; відкликати → знову `401`.
7. **Підсумок дня:** плитки на Home оновлюються після запису; тап відкриває підсумок; ‹ › перемикають дні;
   «+» прокручує до потрібної картки; кнопка «Підсумок дня» в Історії.
8. **Інші пристрої:** відкрити на Android і десктопному Telegram (якщо є).

## 7. Як працювати з проєктом

**Локально (Windows, PowerShell)**
```powershell
docker compose up --build              # база + бекенд (backend/.env з .env.example)
cd frontend; npm ci; npm run dev       # http://localhost:5173, вхід без Telegram
cd backend; python -m pytest           # тести
cd frontend; npm run typecheck         # перевірка типів
```

**Деплой**
```powershell
git add .; git commit -m "..."; git push            # на комп'ютері (PowerShell)
```
```bash
cd ~/sleepguide && git pull && dc up -d --build     # на сервері (SSH); dc = alias на prod-compose
dc ps; dc logs --tail 40 backend
```
`dc` — це `docker compose --env-file ~/sleepguide/.env.prod -f ~/sleepguide/docker-compose.prod.yml`
(у `~/.bashrc` на сервері). Завжди використовуй `dc`, а не голий `docker compose`.

**Структура**
```
backend/app/
  api/         ендпоінти (auth, me, sleep, workout, stress, screen_time, days, tokens, deps)
  services/    бізнес-логіка з доступом до БД
  analytics/   чисті правила (sleep_score, sleep_rules, reminders, stress_rules, ...)
  bot/         aiogram: texts, actions, handlers, reminders (цикл), setup, webhook
  core/        config, db, security (JWT), telegram_auth, api_tokens, rate_limit
  models/ schemas/   таблиці та схеми Pydantic
```
