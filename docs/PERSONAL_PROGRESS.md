# SleepGuide — персональні функції після MVP

Міграція 0009, експорт JSON 1.2. Формула Sleep Score залишається версією 1.0.

## Розпізнавання скриншотів

Головна → Екранний час → Додати / Інший день → Імпортувати скриншот.
PNG/JPEG/WebP до 10 МБ, 20 мегапікселів і 8000 px по стороні. OCR виконується
у Web Worker на пристрої через Tesseract.js 7. Мовні моделі English/Ukrainian,
worker і WASM подаються із власного origin; немає запитів до OCR API або CDN.
Зображення, назви застосунків та розпізнаний текст не передаються backend,
не потрапляють у базу, логи або експорт. Зображення існує в пам’яті до закриття
діалогу. Закриття зупиняє worker; мовні моделі не кешуються в IndexedDB.

Після OCR користувач обирає тривалість зі списку, перевіряє дату й натискає
Зберегти. Для наявного запису потрібне підтвердження заміни, включно з датами
поза вже завантаженим списком. Зміна дати зберігає вибраний OCR total.
Дата, час перед сном та загальний час не вгадуються з графіків. Тижневі середні
й тривалості окремих застосунків можуть з’являтися серед варіантів; вибір людиною
обов’язковий. Ручне введення залишається доступним після помилки розпізнавання.
Формати інших мов і layout кожної версії iOS/Android потребують окремої перевірки.

`npm run dev` / `npm run build` запускають scripts/prepare-ocr.mjs, який копіює
моделі й усі варіанти WASM з lockfile-залежностей у public/ocr. Згенерована папка
не входить у source ZIP/Git; після npm ci вона відтворюється. Початковий JS не
містить OCR engine; великий worker/model завантажується лише при імпорті.
Caddy CSP дозволяє власний WASM, blob worker/image та залишає connect-src self.

## Базові показники й тренди

Інсайти → Твій звичний ритм. GET /api/v1/personal/baselines, JWT.
Останні 7 завершених локальних днів проти попередніх 28, без сьогоднішнього
неповного дня. Для різниці потрібні мінімум 3 / 14 спостережуваних днів.
Основний сон агрегується за днем пробудження; naps й відкриті таймери виключено.
Стрес — середнє щоденних середніх, тож багато оцінок одного дня не переважують
решту. Екран — середнє записаних днів, включно зі справжнім нулем.
Пропуски залишаються невідомими. Тренування — кількість записаних днів за 7 днів;
базове число масштабовано з 28 до 7. Їхній sample — дні покриття щоденника,
а нуль означає відсутність записаних тренувань, не доказ відсутності активності.
Періоди, вибірки й нестача даних видимі. Жодних причинних висновків чи LLM.

## Нагадування за патернами

Налаштування → Нагадування → За моїм ритмом, вимкнено за замовчуванням.
Одна остання основна сесія на день пробудження за попередні 28 днів; час
засинання 18:00–06:00. Мінімум 14 ночей і стандартне відхилення ≤60 хв.
Час переноситься на вісь від полудня, тому 23:55 і 00:05 утворюють медіану 00:00.
Нагадування за 30 хв до медіани, catch-up 15 хв. Без стабільного патерну працює
резервний ручний час, якщо його ввімкнено; інакше нагадування не надсилається.
За відкритого сну вечірнього повідомлення немає. Спільний атомарний marker
з ручним нагадуванням запобігає двом надсиланням за один день розкладу.
Блокування бота вимикає всі три типи налаштувань. Ранкове нагадування збережено.
Перевірено scheduler із тестовим Bot; реальні Telegram-повідомлення не надсилалися.

## Досягнення та тижневі цілі

Інсайти → Тижневі цілі / Досягнення; Налаштування → Тижневі цілі.
GET /api/v1/personal/milestones, PATCH /api/v1/me, JWT. Тиждень — понеділок–неділя
в часовій зоні профілю. Цілі 0–7 днів для основного сну, тренувань, стресу й
екрану; 0 вимикає ціль. Це цілі ведення щоденника. За день максимум один credit,
навіть із кількома записами. Майбутні дні, naps і відкриті таймери виключено.
Зміна налаштувань змінює поточний target; історії минулих тижневих targets немає.
Досягнення: 7/30/100 днів щоденника, 10/50 днів тренувань, 7 ранкових оцінок.
Вони обчислюються з поточної історії: видалення записів може їх змінити.
Відпочинок не скидає накопичення; жодних вимог до Score чи щоденних тренувань.

## Картки для поширення

Інсайти → Створити картку результатів. Період 7 або базові 28 днів, вибір
метрик, preview, PNG 1080×1080. За замовчуванням сон і записані дні тренувань;
стрес та екран додаються окремо. Підписи містять sample, workout baseline
приведено до тижня. Ім’я, Telegram ID, записи окремих днів та самопочуття не
включено. Canvas і файл локальні. Зберегти PNG працює незалежно від наявності
Web Share API; Поширити доступне, якщо браузер підтримує файли. Публічних URL
чи серверного зберігання немає. Реальна відправка третім особам не виконувалась.

## Збір даних і перевірка калібрування Sleep Score

Головна під Sleep Score та Історія → підсумок обраного дня: оцінка ранкового
самопочуття 1–5, добровільна, змінювана й видалювана. Оцінювати слід саме
той ранок. GET/PUT/DELETE /api/v1/personal/feedback/{date}, JWT; запис потребує
завершеного основного сну за останні 180 локальних днів. Upsert за user/date.
Snapshot містить Score, нормовані компоненти, версію та SHA256 контексту ночей,
цілі, bedtime target і timezone. Зміна будь-якого використаного запису чи
налаштування виключає застарілу пару до повторного оцінювання. Cold-start
snapshot не використовується для перевірки ваг. Все експортується у schema 1.2;
видалення акаунта каскадно видаляє sleep_feedback. Досягнення обчислюються.

GET /api/v1/personal/calibration показує останні 180 днів: мінімум 28 придатних
ночей, 3 рівні самопочуття і std Score ≥5 балів. За готовності повертає Spearman
ρ Score/самопочуття та окремих компонентів. Готовність означає достатність для
першого аналізу, а не обґрунтованість зміни формули.

Для оцінювання кандидатів ваг за реальним приватним експортом:

```bash
cd backend
python scripts/calibrate_score.py --export /private/sleepguide-export.json \
  --data-kind real --output /private/score-review.json
```

Інструмент не використовує мережу чи DB, не змінює експорт, код або ваги.
Явно вкажіть походження real/synthetic. Потрібні мінімум 60 придатних пар,
мінімум 20 останніх ночей на temporal holdout і достатня варіація в обох частинах.
Grid 5 балів: duration 20–60, consistency 10–50, debt 5–35, bedtime 0–20,
сума 100. Підбір лише на старішій train-частині, перевірка лише на новішій.
Перевага на holdout ≥0.1 ρ позначає кандидата для ручного перегляду.
Синтетичні fixtures не можуть підтвердити калібрування.
Це перевірка одного користувача зі суб’єктивною порядковою шкалою, не незалежна
популяційна чи медична валідація. Зміна формули потребує реальних даних,
незалежної перевірки й окремого версіонованого релізу. Поточна формула 40/30/20/10
не змінена. Реальних даних в наданому проєкті немає — емпіричне калібрування
залишається відкритим кроком.

## Перевірки й реліз

Локально: PostgreSQL 16, API ownership/upsert/cascade/export/stale snapshots,
межі періодів, midnight/duplicates/irregular patterns, scheduler claims, holdout
isolation, uk/en, frontend interaction tests, typecheck/build/Alembic.
У браузері 375×812: тренди, збереження feedback, PNG preview/download, OCR
англомовного синтетичного screenshot (4h25m та app 1h30m). Перевірка реальних
iOS/Android/Telegram, production deploy, offsite backup і живих bot reminders
залишається зовнішнім кроком. Це source ZIP, не вже розгорнутий реліз.

Додатково виправлено browser fallback для confirm: наявність Telegram SDK сама по собі не означає підтримку popup. Нативне підтвердження використовується лише всередині Telegram із підтримкою Bot API 6.2; помилки повертають браузерне підтвердження, а відмова не схвалює дію. Документація: https://core.telegram.org/bots/webapps#initializing-mini-apps. Локально 244 backend / 40 frontend tests.
