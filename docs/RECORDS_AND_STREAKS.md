# Рекорди вправ і серії записів

Розширення після MVP, 12.10.2026, на основі версії Phase 11.

> Наступне розширення: [історія 90/ALL](HISTORY_RANGES.md); актуальні перевірки —
> 227 backend / 25 frontend. Числа нижче описують етап рекордів/серій.

## Як користуватись

Заверши тренування або додай його заднім числом. Відкрий **Історія → Тренування
→ Вправи** біля потрібного тренування. Створи або вибери вправу, введи її
результат і збережи. Кожен запис — один підхід або одне проходження дистанції.
Записи можна редагувати й видаляти; вправу — перейменувати або видалити разом
із результатами. Видалення вправи не видаляє тренування.

Блок **Рекорди тренувань** в Історії охоплює всю історію незалежно від 7/30 днів.
На **Головній → Серії записів** показані поточна й найдовша серії; розгорни
пояснення для окремих категорій.

## Правила рекордів

- Результати порівнюються лише всередині однієї вправи користувача.
- Силові: найбільша додаткова вага, найбільше повторів, найбільший обсяг
  **одного підходу** = кг × повтори. Біля рекорду — фактична вага, повтори й дата.
  Загальний обсяг тренування та розрахунковий 1RM не обчислюються.
- Власна вага: введи 0 кг; показується рекорд повторів, нульова вага/обсяг не
  показуються як рекорди. Не вводь масу тіла як додаткове навантаження.
- Дистанційні: найбільша дистанція й найменший час **на кожній однаковій
  дистанції**. 1 км та 5 км мають окремі рекорди часу. Метри цілі; час у секундах.
  Дистанцію можна зберегти без часу; час без дистанції не приймається.
- Час результату не може перевищувати тривалість тренування. Перед скороченням
  тренування нижче вже записаного результату треба виправити цей результат.
- При рівності перемагає найраніша дата тренування, потім ID результату.
- Це найкращі записані результати; перший запис теж стає рекордом. Застосунок
  не підтверджує спортивну техніку чи справжність вимірювання.
- Рекорди обчислюються через SQL ranking при читанні. Редагування й видалення
  результату/тренування змінюють актуальні рекорди без окремого кешу в БД.

Назви нормалізуються Unicode NFKC, зайві пробіли прибираються, дублікати
визначаються через casefold. `Bench Press` і ` bench   press ` — одна назва
в акаунті. Синоніми/різні мови автоматично не об’єднуються. Тип вимірювання
незмінний; для іншого руху або типу створи окрему вправу. Ліміти: 100 вправ
на акаунт, 500 результатів на тренування. Підтримуються uk/en.

## Правила серій

Серія — послідовність календарних днів із записами. Один день зараховується
один раз незалежно від кількості записів.

| Категорія | Коли день зараховується |
| --- | --- |
| Загальна | Є хоча б один запис із категорій нижче |
| Сон | Завершений основний сон; дата пробудження; без денного сну |
| Тренування | Завершене тренування ≥1 хв; дата початку |
| Стрес | Є хоча б одна оцінка |
| Екранний час | Є запис дня, включно з явно записаними 0 хв |

Відкриті таймери й майбутні дати не зараховуються. Сьогодні визначається за
поточним поясом профілю; історичні дні беруться зі збережених local_date.
Серія від учора зберігається до кінця сьогоднішнього дня; після пропущеного
повного дня стає 0. Найдовша серія обчислюється за всю історію. Заповнення
пропущених днів заднім числом, редагування або видалення змінюють результат.
Фронтенд перевіряє зміну календарного дня раз на хвилину, також оновлює дані
після мутацій і повернення до застосунку. Це серія ведення історії, а не
оцінка здоров’я або рекомендація тренуватися щодня.

## API й приватність

Усі нові ендпоінти потребують JWT Mini App; Shortcuts-токени не приймаються.

| Метод | Шлях від /api/v1 | Дія |
| --- | --- | --- |
| GET / POST | /exercises | Власні вправи / створити |
| PATCH / DELETE | /exercises/{id} | Назва / видалити з результатами |
| GET / POST | /workouts/{id}/exercises | Результати завершеного тренування / додати |
| PUT / DELETE | /exercise-logs/{id} | Замінити всі вимірювання / видалити |
| GET | /records | Рекорди за всю історію |
| GET | /progress | Дата, пояс і п’ять серій |

Міграція **0008** створює exercises, exercise_logs і складений унікальний ключ
workouts. Складені FK з user_id забороняють прив’язування результату до чужої
вправи/тренування навіть напряму в БД. FK мають ON DELETE CASCADE. Запити
рекордів/серій читають узгоджений REPEATABLE READ snapshot.

Експорт `/me/export` має **schema_version 1.1**, додає exercises/exercise_logs
з ID зв’язків і timestamps; name_key є похідним внутрішнім полем. Рекорди й
серії окремо не зберігаються. Видалення акаунта прибирає нові дані. Чернетка
політики приватності uk/en тепер описує вправи та їхні вимірювання.

Перед production-оновленням зроби бекап; backend запускає `alembic upgrade head`.
Для Phase 11 застосовується 0007 → 0008 без змін старої історії. Відкат 0008
видаляє нові таблиці та результати; для їх повернення потрібен бекап.
Dev-генератор `python -m app.seed.demo` додає дві вправи й шість результатів;
поза ENV=dev відмовляється працювати та не перезаписує наявні дані.

  збереження вводу після помилки, створення вправи, accessible controls,
  серії та попередні перевірки приватності/сесії/тем.
- ruff, typecheck, production build; upgrade/check і downgrade/upgrade.
- Браузер 375 × 812 зі справжньою локальною PostgreSQL: запис 65 кг × 12,
  автоматичні рекорди 65 кг / 780 кг, пояснення категорій серій, без overflow
  і помилок console. Це демо та емуляція ширини, не фізичний Telegram-клієнт.
- JS: початковий bundle 125.22 kB gzip; History 9.64 kB; CSS 5.33 kB.

  і revision 0008 точно збігаються із джерелом. Штатні backup/restore скрипти
  перевірені через локальний Docker-транспорт адаптер до справжніх PostgreSQL
  утиліт; зовнішнє сховище не використовувалось.
