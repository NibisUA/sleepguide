# Шаблони тренувань і відновлення записів

Оновлення 13.10.2026. Міграція **0012**, JSON export 1.2 із додатковими полями.

## Як користуватися

1. Заверши тренування та запиши фактичні підходи / кардіорезультати.
2. Відкрий його журнал підходів → **Зберегти як шаблон** → введи назву.
3. На головному екрані у блоці тренувань вибери **Почати за шаблоном** або
   **Повторити минуле тренування**. В історії можна повторити конкретне тренування.
4. Запускається новий таймер; у журналі видно попередні підходи як план.
   **Використати для нового підходу** заповнює форму. Зміни вагу, повтори чи
   кардіопоказники та збережи лише фактично виконаний результат.

План не створює ExerciseLog і не впливає на рекорди. Рекорди враховують лише
фактичні результати завершених тренувань. Можна зберегти до 50 шаблонів;
кожен містить до 500 підходів із власного завершеного тренування.
Шаблон є копією набору вправ, тому зберігається після видалення тренування-джерела.
Видалення вправи блокує запуск відповідного шаблону: віднови вправу в кошику
або збережи оновлений шаблон. Наявний таймер потрібно завершити перед повторенням.

## Скасування видалення

Після видалення запису є повідомлення з кнопкою **Відновити**. Кошик також
доступний в **Історії** та **Налаштуваннях**; перезавантаження застосунку його не очищає.
Підтримуються сон, тренування, стрес, екранний час, вправи та окремі підходи.
Тренування і вправи відновлюються разом із підходами, які існували на момент видалення.
Зберігаються початкові ID, час, числові значення, категорії екранного часу й план тренування.

Відновлення доступне **30 днів**. Прострочені знімки фізично очищаються під час
наступного відкриття кошика; без відкриття вони можуть залишатися у робочій базі,
але вже недоступні для відновлення. Можна стерти запис із кошика назавжди вручну.
Список показує 200 останніх записів. Раніше видалені до цієї міграції записи
не мають знімків і не відновлюються.

Відновлення атомарне: якщо інтервал перетинає поточний сон / тренування, за цей
день уже є екранний час, повторюється назва вправи, немає батьківської вправи /
тренування або перевищений ліміт, повертається зрозуміла помилка. Поточні записи
не перезаписуються, знімок залишається в кошику. За потреби спочатку віднови
батьківське тренування та вправу, потім окремий підхід. Якщо тривалість тренування
скорочена нижче кардіорезультату, спочатку виправ її.

Знімок та видалення записуються однією транзакцією. Всі зміни серіалізовані
за користувачем; інший акаунт не бачить шаблони / кошик і не може їх відновлювати.
JSON export включає `workout_templates`, `deleted_entries` із знімками та
`workouts[].planned_sets`. Видалення акаунта очищає також шаблони та кошик;
видалення акаунта не можна скасувати. Резервні копії мають окрему ротацію.

## API

- `GET /api/v1/workout-templates`
- `POST /api/v1/workout-templates` — `{name, workout_id}`
- `POST /api/v1/workout-templates/{id}/start`
- `DELETE /api/v1/workout-templates/{id}` — остаточно видаляє тільки шаблон
- `POST /api/v1/workouts/{id}/repeat`
- `GET /api/v1/trash` — метадані без знімків
- `POST /api/v1/trash/{id}/restore`
- `DELETE /api/v1/trash/{id}` — остаточне видалення з кошика

Ці API потребують JWT застосунку. Токени Shortcuts не отримують доступу до кошика,
шаблонів або експорту. Старі DELETE щоденників зберігають відповідь 204.

## Перевірки та розгортання

Перевірені шаблони, повторення без автоматичних результатів, ізоляція акаунтів,
конкурентний запуск, відновлення всіх типів записів, відкат при конфлікті,
повернення точних ID / дробових ваг / категорій, строк відновлення й каскад акаунта.
UI перевірено на заповнення плану без запису, зміну фактичного результату,
збереження / запуск шаблону, вибір правильного запису для Undo та помилки відновлення.

Перед оновленням сервера потрібен резервний дамп. Стандартний запуск backend
виконує `alembic upgrade head`. Міграція додає дві таблиці та `workouts.planned_sets`
з порожнім планом для старих записів. Downgrade 0012→0011 видаляє шаблони та кошик:
це тільки перевірка на одноразовій тестовій базі, не спосіб відкоту production-даних.
На Oracle ця версія ще не розгорнута. Візуальна перевірка у справжньому Telegram
та на телефоні залишається ручною.
