# Phase 9 — інсайти

> Історичний звіт Phase 9. Актуальний стан Phase 10/11 — у [RELEASE.md](RELEASE.md).

Реалізовано 12.10.2026 поверх наданого `sleepguide-phase8.zip`.
Архітектура React / FastAPI / PostgreSQL / Oracle збережена.

## Правила і дані

Двигун — чисті функції `backend/app/analytics/insights.py`, без LLM.
Вікно аналізу: останні 90 місцевих дат пробудження, включно із сьогодні.
Потрібно 14 різних днів із завершеним основним сном; денний сон і відкриті сесії не рахуються.
Кілька основних сесій одного дня агрегуються; час відходу береться з найдовшої.

Записи дня **D−1** порівнюються зі сном, що завершився **D**. Це фіксована домовленість
для MVP, зокрема для відходу після опівночі. Для змінного графіка чи сну, що триває
через кілька календарних дат, така прив'язка може бути неточною.

| Інсайт | Групи | Метрика | Мінімальна різниця |
| --- | --- | --- | --- |
| Екран | Перед сном ≥60 хв / <60 хв | Середня тривалість основного сну | 20 хв |
| Тренування | Є завершене записане тренування / немає записаного | Середня тривалість основного сну | 20 хв |
| Стрес | Середня оцінка дня ≥4 / <4 | Середній Sleep Score | 8 пунктів |
| Відхід | Найкраще фіксоване годинне вікно / решта часу | Середній Sleep Score | 8 пунктів |

У кожній групі має бути щонайменше 5 ночей. Поріг перевіряється **до округлення**.
Для екрана і стресу пропущені записи виключаються; вони не перетворюються на нулі.
Стрес — точне середнє всіх оцінок дня, не максимум і не округлене відображення.
Вікна відходу — місцеві години 00:00–01:00 … 23:00–00:00; рівні середні розв'язуються
детерміновано за годиною. Відображається лише вікно, яке перевищує середнє решти ночей.
Формулювання показують асоціацію, її напрямок, розмір вибірки, період і середні груп.
Відсутність записаного тренування не оголошується доведеним днем без активності.

## API і збереження

- `GET /api/v1/insights`: перерахувати поточні закономірності й повернути до 4 карток.
- `GET /api/v1/insights/progress`: кількість ночей, пороги, кількість пар з екраном/стресом.
- Обидва ендпоінти доступні лише з JWT; токени Shortcuts не приймаються.
- Міграція `0006`: таблиця `insights` з FK `ON DELETE CASCADE`, JSON параметрами,
  i18n-ключем, вибіркою, періодом, версією алгоритму і датою формування.
- Унікальна пара `(user_id, type)` зберігає поточний інсайт кожного типу.
- Повторний незмінений розрахунок зберігає ID і дату; змінений оновлює їх параметри/дату;
  закономірність, що вже не проходить пороги, видаляється з поточного набору.
- Оновлення одного користувача серіалізуються блокуванням рядка `users`, а запити
  всіх таблиць фільтруються за його `user_id`.
- Score використовує наявний алгоритм і контекст історії; окремого Recovery Score немає.

Картки додані на вкладку «Інсайти» й на Home. Записи і зміни налаштувань
інвалідують кеш інсайтів. Без даних є прогрес, за відсутності різниці — пояснення,
при помилці — локалізоване повідомлення і повтор запиту.

## Демо

Лише в окремій dev-базі після міграцій:

```bash
cd backend
ENV=dev python -m app.seed.demo
```

Windows PowerShell:

```powershell
$env:ENV = "dev"
python -m app.seed.demo
```

Створює 60 завершених ночей і пов'язані записи для стандартного dev-входу
`999000001`. Генератор відмовляється працювати поза `ENV=dev` та за наявності
будь-яких записів цього dev-акаунта. Існуючі дані не перезаписуються.
Для перегляду потрібен `DEV_LOGIN_ENABLED=true` у dev-конфігурації.

## Перевірка й деплой

1. `cd backend`: установити `.[dev]`, виконати `ruff check .` і `python -m pytest`.
2. На ізольованій PostgreSQL: `alembic upgrade head`, потім `alembic check`.
3. Для реального інтеграційного тесту задати `TEST_DATABASE_URL` на БД з назвою `*_test`.
   Тест перевіряє паралельний refresh, постійність ID/дати, ізоляцію і каскадне видалення
   створених ним тестових записів. Без змінної він пропускається.
4. Контракт: `python scripts/export_openapi.py`, потім у frontend `npm run gen:api`.
   Комітити `docs/openapi.json` і `frontend/src/types/api.gen.ts` разом зі схемами.
5. `npm run typecheck` і `npm run build`.
6. Перенести перевірені зміни до власного репозиторію; на Oracle виконати наявний
   `git pull` і `dc up -d --build`, перевірити міграцію `0006` і логи.
7. Перевірити Telegram iPhone/Android, нагадування й Shortcuts за `docs/STATUS.md`.

CI додано в `.github/workflows/ci.yml`: ruff, pytest, PostgreSQL 16 і міграції,
контракт без розбіжностей, генеровані типи, typecheck, build.
CI визначено в коді, але його віддалений запуск у GitHub тут не підтверджений.

## Пов'язані зміни Phase 10

- API-типи реально беруться з генерованого контракту через alias-и.
- `staleTime` 30 секунд для загальних запитів і 60 секунд для інсайтів.
- Heatmap відкриває поточний місяць, позначає вибір і вимикає майбутні дні.
- Додані скелетони/повтор запиту; помилки історій більше не показують порожній список.
- Помилки видалення в історіях більше не мовчать.
- Telegram theme/safe-area, колір тексту кнопок, фокус, reduced-motion, aria-мітки.

Phase 10 загалом ще не завершена: потрібні перевірки справжніх Telegram-клієнтів,
повний accessibility-аудит, вимірювання запитів PostgreSQL/EXPLAIN та решта станів UI.
Phase 11 (приватність, експорт/видалення акаунта, бот help/privacy, відновлення бекапів
і серверне зміцнення) залишається наступною роботою після Phase 10.

## Межі локальної перевірки

На 12.10.2026: **162 passed, 1 skipped**, ruff/typecheck/build успішні.
Пропущено реальний PostgreSQL-тест через відсутність PostgreSQL/Docker на цьому хості.
Alembic згенерував SQL ланцюжка 0001–0006 для PostgreSQL без помилок; це не застосування
міграцій до живої бази. CI для таких перевірок підготовлено, але ще не запускалося.
Є одне попередження Starlette щодо подальшої заміни httpx у TestClient.

Перегляд перевірено на ізольованій SQLite QA-базі з адаптацією metadata лише в
тимчасовому локальному runner-і; це не частина архіву і не зміна production-архітектури.
Перевірені чотири картки, групи, uk/en, ширина 375 px, відсутність горизонтального
переповнення, запис стресу й оновлення Home, історія та позиція heatmap.
JavaScript: 421.42 КБ без стискання / 124.69 КБ gzip; CSS: 5.08 КБ gzip.

Початковий архів: 127/129 тестів проходили; два збої були через FakeSession, який
не застосовував INSERT-default `is_nap=False`. Виправлено тестову імітацію БД,
а не замасковано проблему в схемі API. Початковий typecheck і build також пройшли.

Доступу до GitHub/Oracle, токена бота та реального телефона тут немає. Продакшен,
реальні користувацькі дані, налаштування домену, білінг і секрети не змінювалися.
